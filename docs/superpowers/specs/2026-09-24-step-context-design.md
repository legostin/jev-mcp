# Контекст шага, сложение проходов и проба с откатом

Дата: 2026-09-24
Статус: утверждено к реализации

## 1. Проблема

Прогон «самая дешёвая Toyota Camry в Павлодаре» на реальном автомобильном маркетплейсе задал агенту 3 вопроса там, где правильный ответ
был очевиден. Разбор трассы и повторные вызовы JEV показали три причины.

1. **Размытый вопрос.** Шаг `fill_param` искал «поле ввода или выпадающий список для модели». Кнопка «Модель» —
   ровно такой список (0.69), а «Camry» — значение, а не поле (0.13). Тот же вопрос со значением
   («элемент, который ставит модель = "Camry"») даёт Camry 0.99, Toyota 0.96, Павлодар 1.00.
2. **Второй проход заменяет первый.** Первый проход выбрал «Павлодар» (0.55), второй — с другим, узким
   контекстом — «Город» (0.49), и код взял второй. У JEV собственный шум около ±0.08 на одном и том же входе,
   поэтому в ничьей ответ решает случайность.
3. **Чужой контекст.** Подсказка про «Кузов» из прошлой задачи попадала во все вопросы. Эффект на уровне шума,
   но это мусор, который растёт с каждой задачей на сайте.

Статистика по 68 решениям, проверенным исходом шага: при уверенности ≥ 0.9 верно 49 из 49; второй проход с
уверенностью 0.2–0.3 верен в 3 из 4. Низкая уверенность не означает ошибку: для обратимых шагов дешевле
попробовать и проверить, чем спрашивать агента.

## 2. Цели

- JEV получает вопрос о **текущем шаге** со значением, а не о «поле для чего-то». Работает для любого сайта:
  кнопки-значения, выпадающие списки, поля ввода, чекбоксы, календари, сортировка.
- Несколько проходов складываются как свидетельства; расхождение снижает уверенность, но не переворачивает ответ.
- Для обратимых шагов система действует и при уверенности ниже 0.4: пробует лидера, проверяет эффект,
  откатывается и пробует следующего. Агента спрашивает после исчерпания попыток или перед необратимым.
- Быстрее: меньше вторых проходов и вопросов, память сайта без лишнего вызова JEV.

Не входит: доменные «пакеты промптов» (travel, marketplace…). Эксперимент показал, что причина в формулировке,
а не в знании домена; структурные вопросы переносятся между сайтами.

## 3. Контекст шага

### 3.1 Карточка шага

Модуль `src/core/questions/step.ts`:

```ts
interface StepCard {
  kind: string;                 // subintent type: fill_param, pick_date, reveal, apply_sort, submit, dismiss_overlay, …
  do: string;                   // "set the car model to \"Camry\""
  param?: { key: string; about: string; value: Json }; // secret → "[secret]"
}
```

`stepCard(sub, params, extra)` строит карточку для каждого подынтента. Вопросы шага (ground, rerank, выбор опции,
подтверждение памяти) получают `goal`, `step` и отобранные подсказки вместо всех параметров. Вопросы уровня
страницы (assess, decide) по-прежнему видят все параметры и прогресс.

### 3.2 Цели со значением

Функции в `step.ts` строят `Intent` для каждого типа шага:

| Шаг | Цель |
|---|---|
| fill_param (текст/выбор) | `the control that sets the {about} to "{value}": an option or button showing this value, or the field where it is typed or chosen` |
| fill_param (boolean) | `the checkbox or switch for "{about}"` (без изменений) |
| fill_param (secret) | `the input field for the {about}` (значение скрыто) |
| pick_date (открыть) | `the field or button that opens the date picker for the {about}` |
| reveal | `the button, link or tab that shows more search filters where the {about} can be set` |
| apply_sort | `the control that sorts the results {order}, or the sort menu that offers this order` |

Код после выбора решает, что делать с элементом: кнопка с надписью, равной значению, нажимается; поле ввода
заполняется; триггер списка открывается. Эта часть уже есть.

### 3.3 Подсказки с привязкой

```ts
interface Hint { text: string; source: 'task' | 'answer' | 'site'; step?: string; about?: string }
```

- `task` — подсказки из спецификации задачи и `jev_control update`: во все вопросы.
- `answer` — подсказка в ответе на вопрос: запоминается с `step` и `about` того шага, что спросил.
- `site` — подсказки сайта (`site_hints`), в таблицу добавляются колонки `step` и `about`; ответ со
  `scope: "domain"` сохраняется с привязкой.

`hintsFor(card)` отбирает подсказки для вопросов шага: `task` всегда; с `about` — если значимые слова `about`
пересекаются с `about`/ключом параметра шага; только со `step` — если совпадает тип шага; старые без привязки —
если значимые слова текста пересекаются со словами карточки. Вопросы уровня страницы получают все подсказки.

### 3.4 Компактная карточка кандидата

`renderCandidate(model, ref)` в `render.ts` — вид для JEV во втором проходе:

```
e725 button "Camry" <filter> {r4}
in: r4 list < r3 form "…"
row: Модель | [Camry] | Land Cruiser Prado | Land Cruiser | RAV4 | Corolla | …
```

Ряд — элементы той же области, чьи вертикальные центры попадают в высоту элемента, по порядку x (до 10).
Координаты, `class`, «name source» и соседи через границы ряда убираются. `renderElement` для `jev_observe`
не меняется.

## 4. Сложение проходов

`groundByIntent`:

1. **Проход 1** (как сейчас): выбор по пулу кандидатов + noul «есть ли цель».
   Уверенно (`act`) → действуем.
2. **Проход 2**: топ-3 (p ≥ 0.02) в компактных карточках, выбор с вариантом «ничего».
   Отдельные noul «подходит ли X» для нескольких кандидатов больше не задаются (шумны, в решении не участвуют);
   для единственного кандидата проверка остаётся.
3. **Слияние** — чистая функция `fuse(p1, p2, keys)`: P1 перенормируется на множество топ-3 ∪ {none},
   итог — среднее P1 и P2. Уверенность — итоговая вероятность лидера.
4. **Решение**:
   - лидер — «ничего»: `none`, если noul «есть ли цель» ≤ `actNo`, иначе `escalate`;
   - итог ≥ `act`, или оба прохода согласны и итог ≥ `escalate` → `act`;
   - шаг разрешает пробу и итог лидера ≥ `trial.floor` → `try` с упорядоченным списком кандидатов;
   - иначе `escalate`.

`GroundResult` получает `decision: 'act' | 'try' | 'escalate' | 'none'` и `ranked` (итоговые вероятности).
`Intent` получает `trial?: boolean` и `exclude?: string[]` (сигнатуры отвергнутых элементов).

## 5. Проба с откатом

### 5.1 Настройки

В слой уверенности (`confidenceSchema`, все уровни: глобально, домен, задача, на лету) добавляется:

```ts
trial?: { enabled?: boolean; floor?: number; tries?: number }
```

| Пресет | enabled | floor | tries |
|---|---|---|---|
| cautious | false | — | — |
| balanced | true | 0.25 | 2 |
| autonomous | true | 0.15 | 3 |

### 5.2 Какие шаги обратимы

| Шаг | Проверка эффекта | Откат |
|---|---|---|
| fill_param: кнопка-значение | элемент стал выбран/нажат, или URL/форма изменились | повторное нажатие, если состояние переключилось; назад, если сменился URL |
| fill_param: триггер списка | появились опции, и среди них нашлась опция для значения | Escape |
| fill_param: поле ввода | значение в поле; если появились подсказки — нашлась подходящая | вернуть прежнее значение поля |
| fill_param: чекбокс | состояние изменилось | повторное нажатие |
| pick_date: открыть календарь | появился календарь | Escape |
| reveal | появились ≥ 2 новых элемента управления | Escape; назад, если сменился URL |
| apply_sort | URL изменился или открылось меню сортировки с нужным порядком | Escape |
| dismiss_overlay | слой исчез | назад, если сменился URL |

`submit` и всё, что правила безопасности считают необратимым, пробой не выбираются.

### 5.3 Поток

- `Task.ground()` получает `try` → действует по первому кандидату, записывая снимок «до» (URL, значение и
  состояния элемента, открытые слои).
- Проверка не прошла → `rollback(before, el)` → сигнатура элемента добавляется в отвергнутые для этого шага →
  шаг возвращает `retry`. Следующая итерация грунтует без отвергнутых кандидатов.
- Число отвергнутых достигло `tries` → вопрос агенту, в сводке перечислены опробованные элементы.
- Счётчик зацикливания не растёт на попытках пробы: после отката страница та же, но прогресс есть.
- Вызовы JEV, приведшие к пробе, получают метку по исходу (для калибровки).

### 5.4 Память сайта

Для обратимых шагов попадание в память — первый кандидат пробы без вызова `ground.memory_confirm`: провал
проверки → `recordFailure`, дальше обычная грунтовка. Для остальных шагов подтверждение остаётся, но спрашивает
с карточкой шага и принимает запись, если noul не «нет» (раньше требовалось «да»).

## 6. Проверка

- Юнит-тесты: карточки и цели (`step.ts`), отбор подсказок, `fuse`, решение `try`, `renderCandidate` (ряд),
  план отката по двум снимкам.
- Фикстура `filters.html` повторяет типичную раскладку автомобильного маркетплейса: ряды «Город | Алматы | … | Павлодар | ещё»,
  «Марка | Toyota | …», ряд «Модель» после выбора марки, выпадающие списки, поля «Цена от/до», кнопка
  «Показать N объявлений», результаты с сортировкой.
- Evals: случаи шагов (`param` + `value`) рядом с существующими целями; цели строятся тем же кодом, что в
  исполнителе. Точность не хуже текущей (41/41) и новые случаи проходят.
- Живой e2e на `filters.html`: Camry в Павлодаре без вопросов агенту.
- Реальные сайты: общеизвестные международные сервисы (маркетплейс, поиск кода, магазин) — задачи
  с фильтрами и сортировкой; фиксируем число вопросов, шагов, время и стоимость.

## 7. Дополнения по итогам живых прогонов

- **Результаты читает агент.** Задача с `result` заканчивается на странице результатов: JEV применяет
  сортировку сайта для `min/max`, находит главный список и передаёт его агенту строками (одна позиция —
  одна строка, без повторов и интерфейсного мусора, ссылки без трекинга, около 4 тыс. токенов). Выбор
  ответа — за агентом: он отличает товар от аксессуара и спонсорскую строку от результата надёжнее, чем
  разбор полей кодом. `result.extract: "code"` оставлен для массового сбора, `result.pages` читает больше.
- **Значения на другом языке.** Надпись, не совпавшая со значением буквально, проверяется вопросом «это то же
  значение?» (сайт сам выбирает язык интерфейса).
- **Фильтры живут рядом с результатами.** Параметр без поля в форме ждёт страницы результатов; «расширенный
  поиск» пробуется только после поиска. Параметры идут раньше чтения результатов, даже если фильтры вне `<form>`.
- **Ошибки сайта.** Страница ошибки перезагружается один раз, потом шаг назад; повторяющиеся ошибки — вопрос-
  блокер. «Ничего не найдено» — отдельный тип страницы и вопрос агенту.
- **Восприятие текста.** Inline-разметка внутри текста (подсветка запроса, жирные цены) остаётся частью текста.
