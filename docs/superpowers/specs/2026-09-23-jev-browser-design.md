# JEV Browser — спецификация дизайна

Дата: 2026-09-23
Статус: утверждено в брейншторме, ожидает ревью спецификации

## 1. Цель

MCP-инструмент, через который основной агент (Claude Code, Codex и любой MCP-клиент) поручает браузерные задачи
модели **JEV** от TypeSafe. JEV в цикле сам доводит задачу до результата и обращается к основному агенту
только когда действительно не уверен. Инструмент должен:

- понимать структуру страниц на высоком уровне и адаптироваться к незнакомым сайтам;
- не блокировать основного агента: задачи асинхронные, вопросы приходят как события;
- экономить контекст основного агента: вместо сырого DOM отдавать компактные, отфильтрованные JEV срезы;
- давать полную наблюдаемость и отладку процесса принятия решений;
- поддерживать двух провайдеров JEV (OpenRouter и официальный API TypeSafe) с настройкой из инструмента.

### Критерии успеха

1. Сценарий «найди самый дешёвый билет Алматы → Анталия на октябрь на aviasales» проходит от начала до конца,
   с результатом по схеме и не более чем 2 эскалациями на первом прогоне (0 на повторном, благодаря памяти сайта).
2. Eval-набор привязки к элементам: top-1 точность ≥ 90% среди решений, принятых выше порога `act`
   в пресете `balanced`, на фикстурах и сохранённых снимках реальных сайтов.
3. Медианная длительность шага без учёта загрузки страницы ≤ 1.5 с (снимок + 1–3 вызова JEV).
4. Ни один секретный параметр и ни один API-ключ не попадает в запросы к JEV, в трейсы или в ответы инструментов.

### Не входит в объём (YAGNI)

- Собственная LLM-планировщица внутри инструмента: планирует основной агент.
- Модель зрения внутри инструмента: скриншоты отдаются основному агенту.
- Firefox и Safari, удалённые или облачные браузеры, решение капч (капча вызывает эскалацию).

## 2. Что такое JEV и как это влияет на дизайн

JEV (`jev-1.13`) — «System One» модель. Она **не генерирует текст**. На вход она получает `state`
(строку, объект или массив) и набор типизированных вопросов, а на выход возвращает решения с
откалиброванными вероятностями:

| Примитив | Назначение | Ответ |
|---|---|---|
| `choice` | выбрать один вариант из ≤ 255 | `choice`, `probabilities`, `confidence` |
| `score` | позиция на шкале из 2–10 уровней | `score`, `probabilities`, `legend`, `confidence` |
| `noul` | верно ли утверждение | `noul` ∈ [0,1] (без `confidence`) |

Свойства, на которые опирается дизайн:

- ~70–500 мс на вызов (проверено: 0.5–0.7 с через OpenRouter отсюда), $0.042 за 1 млн входных токенов,
  выход бесплатный. Все вопросы одного запроса вычисляются параллельно и изолированно.
- Контекст: 64k на запрос; 32k на `state` + самый длинный вопрос. **Точность падает от нерелевантного шума в state.**
- Только текст, лучше всего английский. Плохо справляется с арифметикой, счётом, датами и многоступенчатой
  косвенностью. Читает инструкции буквально. Уязвима к враждебному содержимому в state.

Следствия для дизайна:

1. **Потоком управляет код, JEV принимает узкие атомарные решения.** Это рекомендация самой TypeSafe.
2. Значения для ввода JEV не придумывает: он выбирает их среди параметров, переданных основным агентом.
3. Числа, даты, сортировку и «минимум по цене» считает код. JEV определяет смысл: что является ценой, какой календарь «туда».
4. Страница режется и фильтруется кодом до 4–8k токенов на вопрос. Большие наборы кандидатов проходят
   иерархический выбор: сначала регион, потом элемент.
5. `choice` всегда кого-то выбирает, поэтому рядом ставится `noul` «нужное вообще есть?».
6. Независимые вопросы идут одним вызовом (speculative fan-out).

### Провайдеры

| Провайдер | Endpoint | Модель по умолчанию | Ключ |
|---|---|---|---|
| OpenRouter | `POST https://openrouter.ai/api/v1/systemone` | `typesafe/jev-1.13` | `sk-or-…` |
| TypeSafe | `POST https://api.typesafe.ai/v1/systemone` | `jev-latest` | TypeSafe API key |

Тело запроса и ответа у обоих одинаковое (`model`, `state`, `questions` → `model`, `answers`, `usage`).
OpenRouter дополнительно возвращает `usage.cost`, `id`, `provider`. Проверено запросом 2026-09-23:
ответ пришёл от `typesafe/jev-1.13-20260917`. Модель по умолчанию закреплена на версии, потому что пороги
калибруются под конкретную версию. Версию, которая фактически ответила, пишем в трейс.

Ошибки: `401` → фатально для задачи, `422` → ошибка построения вопроса, `429`/`529` → экспоненциальный
backoff с учётом `retry-after`. Клиент ограничивает частоту сам (токен-бакет под 1200 запросов/мин и 250k токенов/с,
лимиты настраиваются). Опциональный failover между провайдерами, если настроены оба ключа.

## 3. Архитектура

```
Claude Code / Codex ──stdio──▶ jev mcp          (тонкий прокси, по одному на сессию агента)
                                  │  JSON-RPC по unix-socket (0600)
                                  ▼
                    jevd — демон, один на машину
  ┌─────────────┬──────────────────┬──────────────┬─────────────┬──────────────────┐
  Task Runner    Perception Engine   JEV Client     Site Memory   Trace Store + Debug UI
  └──────────── CDP-сессия (общий интерфейс CdpTransport) ─────────┘
         ▲                                   ▲
  Драйвер extension                   Драйвер chromium
  (ваш Chrome, chrome.debugger,       (отдельный профиль, headless,
   боковая панель, WebSocket)          прямой CDP WebSocket)
```

### Компоненты

| Компонент | Ответственность | Зависит от |
|---|---|---|
| `core/jev` | Клиент System One для обоих провайдеров: ретраи, rate limit, учёт стоимости, версия модели | HTTP |
| `core/cdp` | Интерфейс `CdpTransport` (send, events, sessions фреймов); драйверы `chromium` и `extension-relay` | — |
| `core/perception` | Снимок → модель страницы (элементы, регионы, сигнатуры, виджеты, дифф), рендер срезов в текст | `cdp` |
| `core/questions` | Библиотека шаблонов вопросов к JEV; сборка state по бюджету токенов | `jev`, `perception` |
| `core/runner` | Цикл задачи, пороги, эскалации, извлечение результата | всё выше, `safety`, `memory` |
| `core/safety` | Классификация риска действий (код + JEV), разрешённые домены, маскирование секретов | `questions` |
| `core/memory` | Память сайтов: сигнатуры элементов и подсказки по доменам | хранилище |
| `core/trace` | Запись шагов, вызовов JEV, снимков; ретеншн | хранилище |
| `daemon` | Процесс `jevd`: RPC для прокси и CLI, реестр задач, WebSocket для расширения, HTTP для UI | `core` |
| `mcp` | stdio MCP-сервер: инструменты, доставка событий (channel, прикладывание к ответам) | `daemon` RPC |
| `cli` | Команда `jev`: install, uninstall, settings, doctor, ui, watch | `daemon` RPC |
| `extension` | MV3: CDP-реле через `chrome.debugger`, боковая панель, сопряжение, обнаружение перехвата управления | `daemon` WS |
| `ui` | Debug UI (SPA), раздаётся демоном | `daemon` HTTP |

Монорепо на npm workspaces, TypeScript, Node ≥ 22 (установлен v24.13). Пакеты: `packages/core`,
`packages/daemon`, `packages/mcp`, `packages/cli`, `packages/extension`, `packages/ui`.
Плюс `fixtures/sites/` (тестовые сайты), `evals/` (размеченные снимки и прогонщик),
`skills/jev-browser/SKILL.md` (skill для основного агента).

### Жизненный цикл демона

- Запускается первым прокси `jev mcp` или командой `jev`, если ещё не работает. Процесс отсоединённый,
  единственность обеспечивает lock-файл. `~/.local/share/jev-browser/jevd.json` хранит pid, порты и путь к сокету.
- Завершается после 30 минут простоя: нет подключённых прокси, нет активных задач, нет открытого UI.
- После перезапуска незавершённые задачи восстанавливаются в состоянии `interrupted`.
- Все задачи принадлежат сессии прокси, которая их создала. Вопросы доставляются владельцу, но ответить по
  явному `question_id` может любой клиент, включая человека через UI.

### Драйверы браузера

**chromium.** Находит установленный Chrome или Chromium либо скачивает Chrome for Testing. Запускает его с
`--remote-debugging-port=0` и отдельным профилем `~/.local/share/jev-browser/profile`
(логины в нём сохраняются). Поддерживает headless. Подключается напрямую по CDP WebSocket.

**extension.** MV3-расширение в Chrome пользователя.
- `chrome.debugger.attach` к вкладке задачи; дочерние фреймы подключаются через плоские сессии.
- Команды и события CDP ретранслируются в демон по WebSocket `ws://127.0.0.1:<port>`.
  Порт фиксированный, по умолчанию 47913, настраивается.
- Chrome на время отладки показывает плашку «браузер отлаживается», это неизбежно.
- **Сопряжение:** `jev install` и UI показывают одноразовый код, пользователь вводит его в расширении, и
  расширение получает токен. Демон принимает WebSocket только с `Origin: chrome-extension://<id>` и валидным токеном.
- **Боковая панель:**
  - текущие задачи окна и шаг;
  - кнопки «пауза», «продолжить», «я сам», «отменить»;
  - открытые вопросы с ответом;
  - ползунок порога;
  - подсветка элементов, которые JEV сейчас рассматривает.
- **Перехват управления.** Демон отмечает окна времени, когда он сам отправляет ввод. Доверенный ввод во
  вкладке задачи вне этих окон ставит задачу на паузу со статусом «пользователь перехватил управление».

Если расширение отключилось, его задачи **ставятся на паузу** до переподключения и не падают.

## 4. Perception Engine: понимание страницы

### 4.1 Сбор данных за один проход через CDP

- `DOMSnapshot.captureSnapshot`: DOM с shadow roots, layout rects, paint order, computed styles
  (`display`, `visibility`, `opacity`, `cursor`, `pointer-events`, `position`, `z-index`).
- `Accessibility.getFullAXTree`: роли, вычисленные accessible names, состояния
  (`expanded`, `checked`, `selected`, `disabled`, `focused`, `value`, `required`, `invalid`).
- Фреймы, в том числе cross-origin (OOPIF), через `Target.setAutoAttach({flatten:true})`. Каждый фрейм
  снимается и вклеивается в общее дерево с поправкой координат.
- Скрипт при загрузке документа (`Page.addScriptToEvaluateOnNewDocument`):
  - перехватывает `addEventListener` и отмечает элементы с `click`/`mousedown`/`pointerdown`;
  - ведёт MutationObserver для определения «успокоения» страницы.
- **Готовность страницы:** нет мутаций ≥ 300 мс, нет активных запросов ≥ 500 мс (без long-poll и WebSocket),
  анимации завершены. Максимум ожидания 10 с, настраивается. Действия выполняются только на успокоившейся странице.

### 4.2 Модель страницы (детерминированно, в коде)

**Элементы:**
- интерактивные: ссылки, кнопки, поля, select, contenteditable, ARIA-виджеты, элементы с отмеченными
  click-обработчиками или `cursor:pointer`;
- значимый текст: заголовки, абзацы, ячейки, подписи, `alt` изображений.

Для каждого элемента:
- **Флаги:** видим, во вьюпорте, перекрыт (hit-test в центре и в запасных точках), disabled, текущее значение.
- **Имя:** accessible name. Если его нет: `<label>`, `placeholder`, `title`, `aria-*`, затем ближайший текст
  по геометрии (слева или сверху в пределах порога) и заголовок контейнера.
- **Описание одной строкой:** `textbox "Откуда" value="" placeholder="Город вылета" [required] {in r3 search form}`.
- **Ссылки:** на каждом шаге ref `eN`; долговременная сигнатура из роли, нормализованного имени, тега,
  ключевых атрибутов (`name`, `id` без случайных хвостов, `data-testid`, `type`, `autocomplete`)
  и пути по регионам. Между снимками элементы сопоставляются по сигнатуре, чтобы ref были стабильными.

**Регионы** `rN`:
- landmarks: header, nav, main, aside, footer, form, dialog;
- **оверлеи**: fixed или absolute с высоким z-index, перекрывающие контент (модалки, cookie-баннеры, промо);
- **всплывающие списки**: listbox, подсказки автокомплита, найденные по `aria-expanded`/`aria-controls`/
  `aria-activedescendant` и по диффу после ввода;
- **повторяющиеся структуры**: соседние поддеревья с похожими путями тегов (карточки результатов).

У каждого региона есть описание: роль, заголовок, число элементов, образцы текста.

**Дифф** между снимками: новые, удалённые и изменённые элементы, смена URL, новый оверлей, смена фокуса и значений.

**Гигиена.** Скрытый текст (`display:none`, `visibility:hidden`, `aria-hidden`, нулевой размер, за пределами
клипа) не попадает в модель. Это ещё и защита от спрятанных prompt injection.

### 4.3 Виджеты, которые разбирает код

| Виджет | Что делает код | Что решает JEV |
|---|---|---|
| native `select` | список опций | какая опция соответствует параметру |
| автокомплит | вводит значение параметра, по диффу находит появившийся список | какая строка соответствует параметру |
| календарь | распознаёт сетку дат (`aria-label`, `data-date`, текст ячеек), переводит период в диапазон дат, фильтрует ячейки | какой это календарь («туда» или «обратно») и выбор среди отфильтрованных |
| чекбокс, радио, слайдер | читает и выставляет состояние через AX и ввод | нужное значение по параметру |

### 4.4 Срезы для основного агента

Модель страницы рендерится в компактный текст на разных уровнях:
- `overview`: регионы с описаниями;
- `region rN`: элементы региона;
- `element eN`: подробности и соседи;
- `diff`: изменения с прошлого снимка.

По умолчанию срез укладывается в заданный бюджет токенов.

## 5. Вопросы к JEV

### 5.1 Общая форма state

```jsonc
{
  "goal": "Find the cheapest ticket",          // от основного агента
  "params": {
    "from":     { "about": "departure city", "value": "Алматы" },
    "password": { "about": "account password", "value": "[secret]" }   // секреты маскируются всегда
  },
  "hints": ["The 'Откуда' field is the departure city"],
  "progress": { "from": "entered", "to": "missing" },   // считает код
  "page": { "url": "…", "title": "…", "lang": "ru",
            "regions": { "r3": "form: search, 12 elements, 'Откуда', 'Куда', 'Когда'" },
            "elements": { "e12": "textbox \"Откуда\" value=\"\" {in r3}" } },
  "recent_steps": ["dismissed cookie banner r2"]
}
```

Инструкции вопросов написаны на английском и ссылаются на поля через обратные кавычки
(`params.from`, `page.elements`). Текст страницы находится только в `page` и никогда не попадает в инструкции.
Сборщик state включает только поля, нужные конкретному вопросу, и соблюдает бюджет:
цель 4–8k токенов, жёсткий предел меньше 32k за вычетом самого длинного вопроса.

### 5.2 Библиотека шаблонов

Каждый шаблон — модуль с инструкцией, критериями, сборщиком state и собственным eval.

| Шаблон | Примитив | Вопрос |
|---|---|---|
| `assess.page_kind` | choice | тип страницы: search_form, results_list, item_details, login, captcha, error, checkout, consent, other |
| `assess.overlay_blocks[r]` | noul | мешает ли оверлей работать с основным контентом |
| `assess.overlay_kind[r]` | choice | cookie_consent, promo, region_picker, login_wall, app_banner, other |
| `assess.param_reflected[k]` | noul | отражён ли параметр на странице (только если код не решил сам по значениям полей) |
| `assess.validation_error` | noul | есть ли видимая ошибка валидации |
| `assess.goal_reached` | noul | показывает ли страница то, что требует цель |
| `assess.required_uncovered[e]` | noul | обязательно ли пустое поле и не покрыто ли оно параметрами (приводит к `missing_param`) |
| `decide.next_subintent` | choice | лучший следующий шаг среди кандидатов, сгенерированных кодом |
| `ground.region` | choice | в каком регионе цель под-намерения (beam top-k) |
| `ground.element` | choice | какой элемент (≤ 255, критерии `null`, описания в state) |
| `ground.exists` | noul | есть ли нужный элемент среди кандидатов |
| `ground.rerank` | choice | переранжирование top-3 с полными описаниями и окружением |
| `ground.memory_confirm` | noul | является ли элемент из памяти сайта нужным |
| `widget.suggestion_pick` | choice | строка автокомплита для параметра |
| `widget.option_pick` | choice | опция select, радио или чекбокса для параметра |
| `widget.calendar_role` | choice | роль календаря (depart, return, other) |
| `extract.is_item[r]` | noul | является ли повторяющийся блок результатом по цели |
| `extract.field[i][f]` | choice | какой текстовый лист карточки i является полем f схемы (+ `none`) |
| `safety.action_class` | choice | navigation, input, search_submit, irreversible, other |
| `verify.effect` | noul | дал ли шаг ожидаемый эффект |

### 5.3 Пороги уверенности

Пороги полностью настраиваемые. Каждый уровень перекрывает предыдущий:

1. глобально (`jev_settings`, CLI, UI);
2. для домена;
3. для задачи (`policy.confidence` в `jev_task`);
4. на лету (`jev_control` или ответ на эскалацию, ползунок в боковой панели).

Для каждого вида решения (`assess`, `subintent`, `ground`, `verify`) и примитива задаются:

- `act` — уверенность, начиная с которой действуем сразу;
- `escalate` — уверенность, ниже которой спрашиваем основного агента; между `escalate` и `act` выполняется
  переранжирование (`ground.rerank`) или дополнительная проверка;
- опционально `margin` — минимальный отрыв лидера от второго кандидата (`top1 − top2`);
- для `noul`: `act_yes` и `act_no`. Значение `≥ act_yes` означает «да», `≤ act_no` означает «нет»,
  а всё между ними — «не знаю». В `assess` «не знаю» заставляет код опираться на свои сигналы
  (если их нет, считается «нет»). В `ground.exists`, `ground.memory_confirm` и `verify` «не знаю» приводит к
  повторной проверке через 1 с, а затем к эскалации, если она не отключена.

Ключ переопределения имеет вид `<вид>.<примитив>`: `assess.choice`, `assess.noul`, `subintent.choice`,
`ground.choice`, `ground.noul`, `verify.noul`, `extract.choice`, `extract.noul`.

Допустимы любые значения из [0, 1]. `escalate: 0` (и `escalateOnUnsure: false` для `noul`) отключает
эскалации из-за неуверенности: остаются только `stuck`, `risk_confirm`, `missing_param`, `blocker`,
`off_domain` и `budget`.

Пресеты (стартовые значения, уточняются калибровкой по трейсам):

| Пресет | choice `act` / `escalate` | noul `act_yes` / `act_no` | margin |
|---|---|---|---|
| `cautious` | 0.90 / 0.70 | 0.85 / 0.15 | 0.30 |
| `balanced` | 0.85 / 0.55 | 0.80 / 0.20 | — |
| `autonomous` | 0.60 / 0.20 | 0.65 / 0.35 | — |

Проверка необратимых действий **не зависит от порогов** (раздел 7).

## 6. Цикл задачи

### 6.1 Вход

```jsonc
{
  "goal": "Найти самый дешёвый билет",
  "site": "https://aviasales.kz",                     // или "tab": "<id>" | "current"
  "params": {
    "from":   { "value": "Алматы",  "about": "город вылета" },
    "to":     { "value": "Анталия", "about": "город назначения" },
    "period": { "value": { "from": "2026-10-01", "to": "2026-10-31" }, "about": "даты вылета" },
    "login":  { "value": "…", "about": "email аккаунта", "secret": true }
  },
  "result": { "schema": { "price": "money", "airline": "string", "depart": "datetime", "url": "url" },
              "select": "min(price)" },               // min | max | first | all
  "hints": ["…"],
  "policy": { "confidence": { "preset": "balanced" }, "irreversible": "ask",
              "allowed_domains": ["aviasales.kz"], "max_steps": 60, "max_minutes": 15, "budget_usd": 0.2,
              "max_items": 200 },
  "driver": "extension"                               // extension | chromium; headless для chromium
}
```

Типы значений параметров: строка, число, boolean, диапазон дат `{from,to}`, дата, список строк.
Типы полей схемы результата: `string`, `number`, `money`, `datetime`, `duration`, `url`, `boolean`.

### 6.2 Состояния

`queued → running ⇄ awaiting_input`; `running ⇄ paused`; `running → interrupted` (сбой браузера,
перезапуск демона); финальные: `done | failed | cancelled`. Каждая задача занимает свою вкладку.
Задачи в разных вкладках выполняются параллельно.

### 6.3 Шаг

1. **Наблюдение.** Дождаться готовности, снять страницу, построить модель, посчитать дифф.
2. **Оценка.** Один вызов JEV с пакетом `assess.*` вопросов.
3. **Под-намерение.** Кандидаты генерирует код:
   - `navigate`, `dismiss_overlay(r)`;
   - `fill_param(k)`, `pick_suggestion(k)`, `pick_date(k)`, `set_option(k)`;
   - `submit`, `apply_sort(field,dir)`, `load_more`, `open_item`;
   - `go_back`, `extract`, `done`, `wait`.

   Сначала работают жёсткие правила кода:
   - блокирующий оверлей → `dismiss_overlay`;
   - только что ввели значение и появились подсказки → `pick_suggestion`;
   - все параметры отражены и видна кнопка отправки → `submit`;
   - страница результатов и задана схема → `extract`.

   Если правила не решают, срабатывает `decide.next_subintent`.
4. **Привязка.** Сначала память сайта (`ground.memory_confirm`). Если не подтвердилось:
   фильтр кандидатов в коде (совместимость с намерением, видимость, BM25 по имени и параметру) →
   `ground.region` (beam) → `ground.element` + `ground.exists` → при необходимости `ground.rerank`.
5. **Риск.** `safety.action_class` плюс детерминированные правила (раздел 7).
6. **Действие** через CDP:
   - прокрутка к элементу, клик в неперекрытую точку;
   - очистка поля и ввод (`insertText` для обычных полей, посимвольные `keyDown`/`keyUp` для
     автокомплитов); select, Enter;
   - `DOM.setFileInputFiles` для файлов (только в `jev_act`).
7. **Проверка.** Детерминированные проверки: значение, URL, появление или исчезновение элементов.
   Затем `verify.effect`. Если шаг не удался, пробуется следующий кандидат из распределения (до 2 попыток),
   потом эскалация.
8. **Защита от зацикливания.** Повтор сигнатуры страницы вместе с тем же действием трижды, исчерпание
   `max_steps`, `max_minutes` или `budget_usd` → эскалация `stuck` или `budget`.

### 6.4 Извлечение результата

- Код находит повторяющиеся структуры, `extract.is_item` отфильтровывает блоки, не являющиеся результатами.
- Для каждой карточки и поля схемы: `extract.field` выбирает текстовый лист (все карточки и поля одним
  или несколькими вызовами).
- Код парсит значения: деньги с валютой, числа, время, длительности, абсолютизирует URL. Применяет `select`.
- Если под `select` нужен полный список, код догружает результаты (`load_more` или прокрутка) до конца
  или до лимита `policy.max_items` (по умолчанию 200).

### 6.5 Эскалация (вопрос основному агенту)

```jsonc
{
  "question_id": "q7", "task_id": "t3",
  "kind": "ground",   // ground | subintent | assess | risk_confirm | missing_param | blocker | stuck | off_domain | budget
  "summary": "Не уверен, какое поле соответствует параметру `from` (город вылета)",
  "page": { "url": "…", "page_kind": { "search_form": 0.91, "other": 0.09 },
            "regions": ["r1 header", "r3 search form (12 el.)", "r7 subscribe form (2 el.)"] },
  "decision": {
    "template": "ground.element",
    "asked": "Which element is the input for `params.from`?",
    "candidates": [ { "ref": "e12", "p": 0.48, "desc": "textbox \"Откуда\" value=\"\" {in r3}" },
                    { "ref": "e31", "p": 0.41, "desc": "textbox \"Город\" {in r7}" } ],
    "confidence": 0.37, "thresholds": { "act": 0.85, "escalate": 0.55 }
  },
  "recent_steps": ["…"],
  "screenshot": "jev://t3/q7.png",
  "answer_with": ["pick", "set_param", "hint", "act", "thresholds", "skip", "abort", "continue"]
}
```

Ответы через `jev_answer`:

| Ответ | Смысл |
|---|---|
| `pick {ref}` | выбрать элемент или кандидата |
| `set_param {key, value, about?, secret?}` | добавить или исправить параметр |
| `hint {text, scope: task\|domain}` | подсказка попадает в `state.hints` |
| `act` + `continue` | агент выполнил действие сам через `jev_act` и продолжает задачу |
| `thresholds {...}` | поменять пороги задачи |
| `skip` | пропустить под-намерение |
| `abort` | отменить задачу |

`remember: true` сохраняет разрешение ситуации в память сайта. Задача в `awaiting_input` ждёт без таймаута
падения: через заданное время (по умолчанию 30 минут) она переходит в `paused` и остаётся восстановимой.

### 6.6 Результат

```jsonc
{ "status": "done",
  "result": { "selected": { "price": { "amount": 41230, "currency": "KZT" }, "airline": "…",
                            "depart": "2026-10-14T06:40", "url": "…" },
              "items_count": 38 },
  "evidence": { "url": "…", "refs": ["e204"], "snippets": ["…"] },
  "stats": { "steps": 14, "jev_calls": 29, "escalations": 1, "cost_usd": 0.0011, "duration_s": 48 },
  "trace": "http://127.0.0.1:…/t/t3" }
```

Полный список элементов доступен через `jev_result`.

## 7. Безопасность

- **Необратимые действия** (оплата, заказ, отправка сообщения или формы с последствиями, удаление,
  публикация, изменения аккаунта). Решение принимается как объединение двух сигналов:
  - `safety.action_class`;
  - детерминированные правила: тексты действия (ru и en: «оплатить», «купить», «подтвердить заказ»,
    «отправить», «удалить», pay, buy, place order, submit, delete, publish), URL и `action` формы
    (`/checkout`, `/payment`, `/order`), поля карт (`autocomplete="cc-*"`).

  Если код считает действие необратимым, оно необратимое. По умолчанию `policy.irreversible: "ask"`
  вызывает эскалацию `risk_confirm` при любой уверенности. `"allow"` выставляется только явно, для
  задачи или для домена.
- **Секреты.** Параметры с `secret: true` в state передаются только как `[secret]`. Значение вводит код.
  В трейсах и ответах значение замаскировано, на скриншотах поля с секретами закрашены.
- **Prompt injection.** Текст страницы находится только в `state.page`. Скрытый текст отбрасывается.
  Инструкции и критерии вопросов статичны и принадлежат коду.
- **Домены.** Переход за пределы `allowed_domains` (если задано) вызывает эскалацию `off_domain`.
- **Локальные каналы.**
  - прокси и CLI подключаются через unix-socket с правами 0600;
  - UI работает только на `127.0.0.1`, токен передаётся во фрагменте URL и сохраняется в cookie;
  - расширение подключается через WebSocket с проверкой `Origin` и токеном сопряжения.
- **Ключи.** Хранятся в `~/.config/jev-browser/config.json` (0600) или в окружении (`OPENROUTER_API_KEY`,
  `TYPESAFE_API_KEY`). Через инструменты ключи только записываются, наружу отдаётся маска.
- **Бюджеты** стоимости на задачу и на день.

## 8. Интерфейс MCP

Ответы инструментов компактные. **Любой ответ содержит краткую сводку открытых вопросов задач этой сессии.**

| Инструмент | Назначение |
|---|---|
| `jev_task` | создать задачу (вход 6.1) → `task_id` сразу |
| `jev_status` | состояние задач сессии или одной задачи: шаг, прогресс параметров, открытые вопросы |
| `jev_wait` | ждать `question` \| `done` \| `any` с таймаутом (≤ 55 с) |
| `jev_answer` | ответить на эскалацию (6.5) |
| `jev_control` | pause, resume, cancel; изменить параметры, подсказки, политику или пороги |
| `jev_result` | полный результат, элементы, доказательства, статистика |
| `jev_observe` | срез страницы: `overview` \| `region` \| `element` \| `diff` |
| `jev_find` | запрос свободным текстом → JEV ранжирует элементы → top-k с вероятностями |
| `jev_extract` | извлечение по схеме с `select` на текущей странице |
| `jev_ask` | произвольные `choice`/`score`/`noul` агента про страницу или регион; state собирается автоматически |
| `jev_act` | click, type, select, press, scroll, hover, navigate, back, wait, upload; цель — `ref` или намерение (привязка с порогами); возвращает дифф |
| `jev_tabs` | список, открыть, закрыть, выбрать вкладку; выбор драйвера |
| `jev_screenshot` | изображение страницы или элемента |
| `jev_settings` | get/set настроек (раздел 10) |
| `jev_trace` | трейс задачи или шага; ссылки на Debug UI и на TypeSafe Playground |
| `jev_doctor` | диагностика: демон, расширение, ключ, задержка провайдера, версии |

### Доставка вопросов и событий

1. **Channel push (Claude Code).** Прокси объявляет capability `experimental['claude/channel']` и
   отправляет `notifications/claude/channel`:
   - `content` — краткое описание вопроса или результата;
   - `meta` — `task_id`, `question_id`, `kind`, `status`.

   Срабатывает, если Claude Code запущен с `--dangerously-load-development-channels server:jev-browser`
   (research preview). Без флага уведомления просто игнорируются.
2. **`jev watch <task_id> [--until question|done|any]`.** CLI ждёт события и завершается, печатая его JSON.
   Основной агент запускает команду в фоне, и Claude Code будит его, когда процесс завершился.
3. **Прикладывание к ответам и `jev_wait`**: для Codex и остальных клиентов.

Поле `instructions` MCP-сервера и skill `jev-browser` объясняют агенту эти механизмы и формат ответов.

## 9. Отладка и наблюдаемость

**Трейс шага:**
- снимок модели страницы и скриншот для человека;
- каждый вызов JEV: state как отправлен и число токенов, вопросы, ответы, распределения, пороги,
  версия модели, стоимость, задержка;
- под-намерение, действие, дифф;
- разбивка времени: ожидание готовности, снимок, JEV, действие.

**Хранение.** SQLite (индекс, вызовы, шаги) и файлы снимков в `~/.local/share/jev-browser/traces/`.
Ретеншн по умолчанию 7 дней и 2 ГБ.

**Debug UI** (`jev ui`):
- **Лента задачи** с распределениями вероятностей и отметкой порогов.
- **Инспектор страницы**: регионы и элементы. Клик подсвечивает элемент в живом браузере.
- **Переигрывание шага**: тот же запрос к JEV с правленными вопросами, state или порогами.
  Ссылка «открыть в TypeSafe Playground» в формате `https://console.typesafe.ai/decode#share/<lz-string>`.
- **Калибровка**: диаграмма надёжности (уверенность ↔ правота) по шаблонам. Правоту размечают `verify` и
  ответы агента. Рекомендация порогов для заданной доли эскалаций.
- **Входящие вопросы**: человек может ответить из UI.
- **Память сайтов**: просмотр, правка, удаление.
- **Настройки.**
- **Экспорт трейса** в архив; импорт для офлайн-переигрывания и превращения в регрессионный тест.

## 11. Память сайтов

- Запись: `(домен, page_kind, под-намерение/параметр) → сигнатура элемента`, плюс вес, счётчики
  успехов и неудач, время последнего использования. Подсказки уровня домена хранятся отдельно.
- Пишется автоматически после успешного `verify` и по `remember: true` в ответах агента.
- Используется как быстрый путь (`ground.memory_confirm`). После неудачи вес уменьшается, после
  двух неудач подряд запись отключается.
- Хранится в SQLite рядом с трейсами. Редактируется в UI.

## 12. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| JEV 429/529, таймаут | backoff с `retry-after`, до 5 попыток; при `failover` — другой провайдер |
| JEV 401 | задача `failed`, сообщение с подсказкой `jev doctor` |
| JEV 422 | эскалация `stuck` с деталями запроса (ошибка шаблона) |
| Элемент исчез или сдвинулся перед действием | снять страницу заново, найти по сигнатуре; если не нашёлся — привязать заново |
| Вкладка закрыта или упал процесс страницы | задача `interrupted` с последним URL; `resume` открывает его и продолжает |
| Расширение отключилось | задачи этого драйвера `paused` до переподключения |
| Перезапуск демона | незавершённые задачи становятся `interrupted` |
| State не влезает в бюджет | код сужает выборку (меньше регионов и кандидатов), лимит не превышается |
| Зацикливание, лимиты | эскалация `stuck` или `budget` с историей шагов |

## 13. Тестирование

- **Unit (core):**
  - сборка модели страницы на сохранённых снимках (DOMSnapshot + AX) реальных сайтов;
  - имена элементов, регионы, повторяющиеся структуры, календари, дифф, сигнатуры;
  - сборщик state и бюджет; правила безопасности; парсеры значений.
- **Клиент JEV:** контрактные тесты на записанных ответах; живой smoke-тест при наличии ключа в окружении.
- **Фикстурные сайты** (`fixtures/sites/`): cookie-баннер, промо-модалка, автокомплит, календарь, native select,
  список результатов с «ещё», iframe, shadow DOM, форма логина, страница оплаты (для проверки `risk_confirm`).
  E2E-тесты цикла через headless-драйвер `chromium`, без интернета, с записанными ответами JEV.
- **Eval-набор** (`evals/`): размеченные снимки «намерение → правильный элемент / тип страницы / поле».
  Прогон на живом JEV считает точность и калибровку по шаблонам и перебирает пороги.
  Любое изменение шаблона вопроса требует прогона eval.
- **Расширение:** Chromium с загруженным unpacked-расширением; сопряжение, реле CDP, пауза при перехвате управления.
- **Ручной приёмочный сценарий:** aviasales из раздела 1.
