# Выводы по архитектуре после живых прогонов

Дата: 2026-09-24
Статус: принято; пункты 1–5 раздела «Решения» реализуются сразу

## Контекст

Прогоны: фикстуры, поиск репозиториев, поиск по новостному агрегатору, крупный маркетплейс, поиск авиабилетов,
мастер подачи объявления на тестовом стенде. Ниже то, что подтвердилось, и что меняется в архитектуре.

## Что подтвердилось

- **Роли.** JEV — быстрые типизированные решения по ходу навигации (какой элемент, сработало ли, что за страница).
  Агент — план и чтение итогов. Разбор списков результатов в JEV был хрупким; передача списка агенту это решила.
- **Формулировка важнее порогов.** Значение в вопросе (0.13 → 0.99), запасной вопрос о поле (0.4–0.5 → 0.8–1.0),
  карточка кандидата с рядом. Низкая уверенность чаще означает размытый вопрос. Шаблоны вопросов меняются только
  с регрессионным набором evals.
- **Действие → проверка эффекта → откат** — основной цикл для обратимых шагов; он убрал большинство вопросов.
- **Сбои на реальных сайтах — в основном восприятие**, а не JEV: inline-разметка в тексте, затемнения с подсказками,
  combobox как список, фильтры-ссылки, календари с подтверждением и поздними ценами, неактивные вкладки мастера.
- **Только общие правила.** Каждое исправление — через структуру страницы; нейтральные фикстуры-шаблоны; живые
  прогоны на известных сайтах.

## Решения

1. **Форма должна служить цели.** Перед заполнением параметров оценка страницы спрашивает, ведёт ли форма к цели
   (вход, выбор раздела, ввод данных) или это посторонняя форма (поиск по сайту, когда цель — подать объявление).
   Если нет — шаг «вход в нужный раздел»: кнопка или ссылка, которая начинает то, что просит цель, с проверкой
   эффекта и откатом; не нашлась — вопрос агенту. Этапы крупной цели по-прежнему может задавать агент.
2. **Мастера и обязательные поля.** Элементы с `pointer-events: none` считаются неактивными (неактивные вкладки
   шагов больше не «перекрыты»). Политика `policy.fill_required: "ask" | "any"`: при `"any"` обязательные выборы
   без параметра (список, группа радиокнопок, выпадающий список) получают первый допустимый вариант; текстовые
   поля и согласия по-прежнему спрашиваются. Группа радиокнопок без выбора в форме мастера считается обязательной.
3. **Задачи переживают перезапуск демона.** Незавершённые задачи восстанавливаются из трассы в состоянии
   `interrupted` с параметрами, прогрессом и адресом; `resume` находит вкладку с этим адресом или открывает новую.
4. **Оценка риска учитывает цель.** Детерминированные правила (оплата, заказ, публикация, удаление, данные карты)
   остаются. Вопрос JEV о необратимости задаётся с целью и шагом в контексте, и одного JEV достаточно только при
   высокой уверенности; вход, поиск и переход дальше по мастеру вопросов не вызывают.
5. **Общая вкладка с человеком.** Прокрутка — не вмешательство; поздняя доставка своего ввода распознаётся.
   После возврата управления (resume) задача перепроверяет введённые значения, чтобы принять то, что человек
   сделал сам, и продолжает с нового состояния страницы.

## Дальше

- Больше вопросов в одном вызове JEV; оценка страницы и поиск элемента параллельно, где они независимы.
- У каждого вывода инструментов бюджет токенов и фильтр приватности по умолчанию.
- Версия протокола MCP ↔ демон и явное сообщение «нужен перезапуск MCP» после обновления.
